### Exact implementation coverage

- Implementation = an **assignment that references the built-in id**. No custom copy of the definition is deployed.
- Evaluator `azure.search.public-network-access` v1.0.0 is selected only when policy kind, source kind
  (`BUILT_IN`), definition id, pinned version **and** the canonical content digest of the definition all
  match the verified copy, and parameters are exactly `{effect}` with an allowed value. Anything else gets
  **no evaluator** and an `UNSUPPORTED` assessment (tested).
- Configuration: `publicNetworkAccess` compared case-insensitively to `Disabled`. Missing values are
  `UNKNOWN`; the provider default is **not** inferred.
- Requests: `PUT`/`PATCH` of `Microsoft.Search/searchServices` within the assignment scope with effect
  `Deny` and enforcementMode `Default`. `DELETE` is not denied. `PATCH` without the property is `UNKNOWN`
  (merge semantics not modelled). Other resource types are not denied by this control.
- Exemptions: `RESOURCE` and `SCOPE` granularity (MG/subscription/RG/resource) representable with native
  expiry. Exemptions are per assignment: an exemption on an existing audit assignment does not exempt from
  a new Deny assignment (the package re-issues exemptions against the new assignment).

### Not verified / unsupported (Azure)

- Assignment-level definition version pinning (`definitionVersion`) is not emitted; the pinned version and
  digest are recorded in assignment metadata for drift detection instead.
- Default value of `publicNetworkAccess` when absent.
- Policy Insights evaluation timing; observations are fixtures.
- `Enroll` enforcement mode and identity-based exemption selectors (`userPrincipalId`, `groupPrincipalId`): `UNSUPPORTED` in this MVP.
- The policy reference index page (`azure-ai-docs/articles/search/policy-reference.md`, ms.date 03/25/2026) includes an autogenerated table from a repository that was not reachable; the definition JSON itself was used instead.

## AWS: protect the S3 Block Public Access baseline with an SCP (UNVERIFIED, DEMO-ONLY)

Corroborated only via web-search excerpts of these official pages (no primary fetch):

| Topic | URL | Statement used |
|---|---|---|
| SCP scope | https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html | SCPs do not affect users/roles in the management account or service-linked roles; they restrict member-account principals including root; they do not grant permissions. |
| Inheritance | https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps_evaluation.html | A Deny at any level applies to all descendants; an Allow is needed at every level; a lower-level Allow cannot override an inherited Deny. |
| Syntax | https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps_syntax.html and `..._examples_general.html` | Deny statements with `ArnNotLike` on `aws:PrincipalArn` to exempt administrative roles. |
| Actions | https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeletePublicAccessBlock.html, `API_control_PutPublicAccessBlock.html` | Bucket-level Put/Delete use `s3:PutBucketPublicAccessBlock`; account-level Put/Delete use `s3:PutAccountPublicAccessBlock`. |
| Block Public Access | https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html | Account/organization settings apply to all buckets and override bucket-level settings. |
| Organizations S3 policies | https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_s3.html | Central management of Block Public Access for member accounts. **Recorded as a native alternative only.** |

### Exact implementation coverage

- One supported template (`template:aws.scp.protect-s3-block-public-access` v1.0.0):
  `Deny` `s3:PutAccountPublicAccessBlock` + `s3:PutBucketPublicAccessBlock` on `*` unless
  `ArnNotLike aws:PrincipalArn` matches 1–5 exempt administrative role patterns. The document must equal the
  template rendering of its parameters (digest match); any other SCP document gets no evaluator.
- **No audit mode.** Any `effect`/`Audit`/`enforcementMode` setting on an SCP implementation or ring is
  `UNSUPPORTED`. Observation is offline assessment only. No "audit SCP" is ever emitted (tested).
- Baseline prerequisite: account-level Block Public Access fully enabled with fresh provenance, plus
  evidence that an exempt administration path exists. Missing → `PREREQUISITE_MISSING`; insecure →
  `PREREQUISITE_INSECURE` (blocks the ring).
- Requests: only the two protected actions are evaluated. Management account, service-linked roles and
  exempt principals are not denied; everything else in scope is `PREDICTED_DENIED`, **including
  strengthening changes** (the SCP cannot inspect requested values; no condition key is invented for that).
  `CreateBucket` and bucket-policy edits are not restricted by this SCP.
- Effective bucket protection = account-level OR bucket-level per setting. Directory buckets are excluded.
  A bucket with no bucket-level configuration is only treated as "none configured" when the collector
  explicitly observed that (`PublicAccessBlockConfigurationStatus: NOT_CONFIGURED`).
- Exceptions: `RESOURCE` (one bucket) → `REQUIRES_DIFFERENT_MECHANISM` (cannot override account/org
  protection); `SCOPE`/`PRINCIPAL` under an inherited externally managed deny → `UNSUPPORTED`; account
  omission only when attachments are per account; principal patterns via a reviewed implementation
  revision. **No native expiry** → removal handoff on expiry (tested).
- The SCP is never described as a universal prohibition on public buckets.

### Not verified / unsupported (AWS)

- SCP size quotas and statement limits.
- Whether any S3 condition key exposes requested Block Public Access values (assumed none).
- Directory bucket Block Public Access semantics.
- Interaction between Organizations S3 policies and SCP-protected account settings.
- Real policy ids (`p-…`) are assigned by AWS Organizations and must be reported by receipts; fixtures use `p-FIXTURE-0001`.
